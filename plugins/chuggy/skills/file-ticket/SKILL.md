# Filing a ticket

Follow the filing steps in the chuggy MCP server's own instructions; they
are the authority and this page does not copy them.

Draft the brief from what the person said and what the repository shows:

- a **title** that names an outcome, not an activity;
- the **intent**, in the person's words, naming the problem and what to
  build;
- the **acceptance**: how the change is verified;
- the **constraints**: what not to touch.

[A ticket](https://github.com/kasofsk/chuggy-docs/blob/main/docs/tickets.md)
describes the brief's fields. Show the draft and file it once the person
agrees.

If a call answers with a sign-in address, relay it to the person in full at
once, then retry after they sign in.

If there is no chuggy server among the MCP servers, use the `setup` skill
(`/chuggy:setup`), or read its `SKILL.md` by its path if the plugin was
installed in this session and has not been reloaded.
